## Ticketing-Konventionen (gelten für alle Tickets)

- **Ablage:** je Ticket eine Datei `plans/phase-c/TICKET-NN-<slug>.md`; zusätzlich ein Index
  `plans/phase-c/00_README.md` (Übersicht + Abhängigkeitsgraph + Status).
- **Sprache:** Deutsch (Code/Variablen englisch), wie im Restprojekt.
- **Self-contained:** jedes Ticket beginnt mit einem **Kontext-Boilerplate** (3–4 Sätze: was
  ist das Projekt, PyOD-Interface, wo liegen Daten, Onset-Logik) + Verweis auf
  `docs/methoden/`, damit ein kalt startender Agent sofort arbeiten kann.
- **Additiv-Regel:** Tickets legen **neue Dateien** an, wo möglich. Edits an *shared files*
  nur **additiv** (Funktionen/Einträge anhängen, nichts Bestehendes umschreiben) — siehe
  Ownership-Matrix.
- **Kein Notebook-Sharing:** jedes Ticket mit Demo legt ein **neues** marimo-Notebook mit
  der unten reservierten Nummer an; bestehende Notebooks bleiben unangetastet.
- **Verifikation Pflicht:** jedes Ticket headless ausführbar (`uv run python notebooks/NN_*.py`
  bzw. `uv run python -m ...`), Exit 0, erzeugt sein Artefakt in `reports/`. Keine Regression
  in den bestehenden Notebooks.

### Ticket-Template (Struktur jeder Datei)
```
# TICKET-NN: <Titel>
Stream · Priorität · Aufwand (S/M/L) · Abhängigkeiten · Status
## Kontext (Boilerplate + ticket-spezifisch)
## Ziel
## Zu erstellende/ändernde Dateien   (markiert: NEU / additiv)
## Schnittstellen-Kontrakt           (Signaturen, Registry-Name, Rückgaben)
## Umsetzungshinweise                (welche bestehenden Utilities/Docs wiederverwenden)
## Akzeptanzkriterien                (messbar)
## Verifikation                      (konkrete Befehle + erwartete Artefakte)
## Konfliktvermeidung                (shared files, additive-only)
## Referenzen                        (docs/methoden/...)
```

### Shared-File-Ownership (Konfliktvermeidung)
| Datei | Eigentümer-Ticket | Regel für andere |
|---|---|---|
| `detectors/base.py` | **T01** (Auto-Discovery-Refactor) | danach niemand mehr — neue Detektoren self-register via `FACTORIES` |
| `data.py` | additiv: T02 (`make_windows`), T03 (`load_semisupervised`) | nur anhängen, Bestehendes nicht ändern |
| `report.py` | **T11** (Asset-Generator) | andere editieren es nicht |
| `pyproject.toml` | additiv: T04 (minisom), T08 (ruff) | je via `uv add` / eigener `[tool.*]`-Block |
| `eval/plots.py` | additiv: neue Plot-Funktionen anhängen | sonst Plot im eigenen Notebook |
| `notebooks/*` | je Ticket eigene **neue** Nummer (s. u.) | bestehende nie editieren |
