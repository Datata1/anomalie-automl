# Planning: AutoML für Anomaliedetection (TEP) — Phase B (Implementierung)

## Kontext

Recherche-/Example-Projekt: **Welche AutoML-Methoden gibt es für Anomaliedetection?**,
demonstriert am Tennessee-Eastman-Process (TEP). Für Vorlesung „ML in der Prozessindustrie"
inkl. PowerPoint. Roter Faden: AutoML-für-AD ist schwer, weil im **unüberwachten** Fall
Labels für Modellselektion/HPO fehlen — TEP-Labels dienen als **„Oracle"-Obergrenze**.

**Phase A (abgeschlossen):** kuratierte Methoden-Doku unter [docs/methoden/](../../Documents/auto-ml/docs/methoden/)
(16 Dateien) — 3 Rahmendok., Kernproblem „Modellselektion ohne Labels", 6+1 AD-Methoden,
4 AutoML-Strategien, Referenzen. Jedes AD-Dok enthält Code-Skizzen, Hyperparameter-Bereiche
und Library-Hinweise.

**Phase B (dieses Planning):** ein sauberes, einfaches, **lauffähiges** Example-Projekt, das
die 3 Settings (unsupervised / semi-supervised / supervised) × 4 AutoML-Strategien (HPO,
Frameworks, Meta-Learning, Ensembling) demonstriert.

### Verifizierter Repo-Zustand
- `uv`-Projekt, Python 3.13, kein `[build-system]` (Application-Projekt → top-level Package
  ist direkt importierbar, kein Build-Setup nötig).
- **Alle 4 Parquet-Dateien liegen lokal vor** (`data/TEP_{FaultFree,Faulty}_{Training,Testing}.parquet`)
  → Implementierung ist real ausführbar/verifizierbar.
- **Schema bestätigt:** 55 Spalten = `faultNumber`, `simulationRun`, `sample` + `xmeas_1..41`
  + `xmv_1..11` = **52 Features** (11 XMV, nicht 12). Doku-Notiz in `01_datensatz_tep.md`
  kann beim Umsetzen auf „bestätigt" gesetzt werden.
- Vorhandene Artefakte: [eda_dataset.ipynb](../../Documents/auto-ml/eda_dataset.ipynb) (bleibt),
  leerer `reports/`-Ordner (für Ausgaben nutzen).

### Abgestimmte Entscheidungen (Phase B)
- **Aufbau:** *vertikaler Slice zuerst* — erst dünne End-to-End-Pipeline lauffähig, dann
  Methode für Methode erweitern.
- **Deps pragmatisch & getiert:** Kern = `pyod`/`scikit-learn` + `optuna` + `marimo` (sicher);

## Architektur

**Leitprinzip:** auf dem **PyOD-`BaseDetector`-Interface** standardisieren
(`fit(X)` / `decision_function(X) → score` (höher = anomaler) / `decision_scores_` /
`threshold_` / `contamination`). Klassische Detektoren *und* torch-AE teilen so dieselbe API
→ jede AutoML-Strategie funktioniert mit jedem Detektor. Eigencode nur für das, was PyOD
nicht abdeckt (LSTM-AE-Sequenzen, DeepSAD, SOM — alles optionaler Stretch).

```
automl_ad/                      # top-level Package (ohne src/, da Application-Projekt)
  config.py                     # Pfade, FEATURE_COLS, ONSET_TEST=160/ONSET_TRAIN=20, Seeds, Subsample-Defaults
  data.py                       # load_split(), make_labels(), fit_scaler(), Run-Level-Split, (Windowing später)
  detectors/
    base.py                     # AnomalyDetector-Protocol (= PyOD-Signatur) + Factory-Registry {name: ()->BaseDetector}
    classical.py                # dünne Factories: IForest, OCSVM, PCA, ECOD (aus pyod.models.*)
    autoencoder.py              # pyod.models.auto_encoder.AutoEncoder (torch); LSTM-AE optional
  automl/
    hpo.py                      # run_optuna(factory, space_fn, X_good, X_val, y_val, metric, n_trials, pruner)
    selection.py                # select_oracle(cands,X_val,y_val) vs select_internal(cands,X) (Konsens/EM-MV)
    ensemble.py                 # standardizer + average/maximization (pyod.models.combination)
    frameworks.py               # FLAML-Wrapper (supervised Klassifikation)
    metaod.py                   # guarded import metaod; sonst Mini-Meta-Selection-Fallback
  eval/
    metrics.py                  # roc_auc, pr_auc(AP), best_f1, detection_delay, false_alarm_rate, summarize()
    plots.py                    # score_timeseries(onset+threshold), per_fault_heatmap, comparison_bars → reports/

notebooks/                      # marimo-Apps (reine .py), importieren aus automl_ad
  01_baselines.py               # VERTIKALER SLICE: load→scale→IForest/OCSVM(default)→eval→plots
  02_hpo.py                     # Optuna-HPO + Multi-Fidelity, Default vs. getunt, Oracle vs. label-frei
  03_frameworks_supervised.py   # FLAML-Klassifikation + RF-Baseline, „Klassifikation vs. AD"
  04_selection_ensemble_metaod.py  # Ensembling + MetaOD, label-frei vs. Oracle (Kernaussage)
  00_eda.py                     # optional: EDA nach marimo portiert (Jupyter-Notebook bleibt bestehen)
```

### Kern-Schnittstellen (Signaturen)

- `data.load_split(faults=None, n_train_good_runs=25, n_test_good_runs=20, n_test_fault_runs=20, seed=0)`
  → `(X_train_good, X_test, y_test, meta_test)`; Split **nach `simulationRun`** (disjunkt),
  `StandardScaler` nur auf Gutdaten gefittet.
- `data.make_labels(df, split)` → punktweises `y` über Onset-Logik
  (`(faultNumber!=0) & (sample>160)` für testing; `>20` für training).
- `detectors.base.REGISTRY` → `{"iforest": lambda **hp: IForest(**hp), ...}` für Austauschbarkeit.
- `eval.metrics.summarize(y_true, scores, meta)` → dict{roc_auc, pr_auc, f1, detection_delay,
  far}.
- `automl.hpo.run_optuna(...)` → `(best_params, study)`; Objective-Varianten: **supervised**
  (ROC-AUC auf Labels) und **label-frei** (interne Metrik) — Schalter `metric=`.
- `automl.selection.select_oracle/ select_internal` → wählt aus Kandidatenliste; liefert die
  **Oracle-vs-label-frei-Gegenüberstellung** (Projekt-Kernaussage).

## Dependencies (uv, getiert)

```bash
# Kern (sicher unter Py 3.13)
uv add pyod scikit-learn optuna marimo
# Deep Learning (für AutoEncoder) — eigene optionale Gruppe
uv add --optional dl torch
# Supervised AutoML
uv add --optional supervised "flaml[automl]"
# optionale Extras (Installierbarkeit prüfen; sonst Eigenbau-Fallback)
uv add --optional meta metaod
uv add --optional som minisom
```
- `pyod` deckt IForest/OCSVM/PCA/ECOD/AutoEncoder/DeepSVDD + `combination`/`standardizer` ab
  → wenig Eigencode.
- **auto-sklearn bewusst nicht** (Py-3.13/Linux-Risiko) → FLAML als Ersatz.
- torch ist der schwere Block (eigene Gruppe, damit Kern auch ohne installierbar bleibt).
- `metaod` zuerst testen; bei Konflikt: kleine eigene Meta-Selection (Performance-Matrix über
  wenige Subsets + Meta-Feature-KNN) als Demo desselben Mechanismus.

## Konventionen & Fallstricke (aus Phase A übernommen)

- **Run-Level-Split** (nie zeilenweise), Scaler nur auf Gutdaten — sonst Leakage.
- **Onset beachten:** `faultNumber!=0` ≠ „jede Zeile anomal" (Testing: Fehler ab Sample 161).
- **Score-Konvention:** überall „höher = anomaler" (PyOD-Default).
- **Subsampling auf Run-Ebene** (Default ~20–25 Runs/Fehler) für schnelle, reproduzierbare
  Demos; Seed fix.
- **Label-freie Selektion** ist der Normalfall; Labels nur als explizit markiertes Oracle.
- Details: [docs/methoden/02_evaluationsprotokoll.md](../../Documents/auto-ml/docs/methoden/02_evaluationsprotokoll.md)
  und [.../00_modellselektion_ohne_labels.md](../../Documents/auto-ml/docs/methoden/automl-strategien/00_modellselektion_ohne_labels.md).
